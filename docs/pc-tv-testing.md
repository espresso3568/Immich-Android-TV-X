# 在 Windows 測試 Immich TV Plus

這台 PC 已安裝官方 Android Emulator，並建立 Android TV API 36、720p、2 GB RAM 的虛擬電視。Android 官方支援以 [虛擬 TV 裝置測試 TV App](https://developer.android.com/training/tv/get-started/create#run-on-a-virtual-device)。目前使用的是 Android TV 系統映像，可驗證本 App 的 TV 操作；不是 TCL C765 的韌體複本，首頁也不保證與 Google TV 實機相同。

## 開啟與操作

1. 在專案資料夾雙擊 **`Start-TV-Test.cmd`**，等待模擬器開機。腳本會檢查已簽署的 Release APK，需要時安裝，並自動開啟 Immich TV Plus，無須重新編譯。同一份 APK 已安裝時會跳過重裝，縮短等待。
2. 首次使用時，在 App 內輸入自己的 Immich 網址與 API Key。模擬器是獨立裝置，登入不會影響電視或手機。
3. 同時會出現 **Immich TV Plus - PC Remote** 遙控器視窗。請用滑鼠點這個視窗的「上／下／左／右／確認／返回」，不必直接點電視畫面；這個 TV 裝置設定為無觸控，滑鼠點畫面無法取代所有遙控操作。遙控器也能接收方向鍵、Enter 與 Esc。若電視停在系統首頁，可按遙控器的「開啟 Immich TV Plus」。
4. 進入設定 → Screensaver，類型選「相簿」，勾選多本相簿後使用「立即開始」預覽。預覽會重新讀取完整清單並洗牌。
5. 測試完關閉模擬器與遙控器視窗。之後再次雙擊入口會沿用登入與設定；一般啟動不會清除資料。

### 快速貼上 API Key

1. 在 PC 複製 API Key，只複製金鑰文字。
2. 用遙控器選到電視上的 **API Key** 欄位，按「確認」，進入文字編輯狀態。
3. 點遙控器的 **「取代並貼上剪貼簿文字」**；也可以在遙控器視窗按 **Ctrl+V**。不必切換到電視視窗。這會先全選欄位，再貼入新值，避免接在舊 Key 後面。
4. 貼上後再完成欄位編輯，最後自行選「Submit／提交」登入。貼上按鈕不會自動提交登入。

貼上會取代目前編輯欄位的全部文字。伺服器網址也能用相同方式貼上，目前接受英文／ASCII 文字。按鈕只在使用者操作時讀取剪貼簿，把文字送到指定模擬器中正在編輯的 Plus 欄位，不寫入檔案、紀錄或程序命令列。

目前入口會選取 `artifacts` 中版本號最高的正式 APK，更新會保留原有登入與設定。舊版只檢查登入欄位格式，進主畫面不代表通過伺服器認證；1.0.1 起提交時先向 Immich 驗證，失敗就留在登入頁。1.0.2 再修正登入後首頁保留舊 Key 的問題，成功時會重建主畫面工作階段。可到「設定 → Server」使用原有 Key 或填入臨時測試 Key，再按「Submit／提交」檢查。網址填主網址，App 會自動補上 `/api/`。不需要在對話中提供 Key。

先前開發驗證使用的假伺服器登入與色塊資料，已在本次準備供手動操作時清除。請使用自己電腦可連到的 Immich 伺服器網址；若 Immich 在同一台 PC，模擬器內的 `localhost` 指向虛擬電視本身，可使用主機的區網 IP，或 Android Emulator 的主機別名 `10.0.2.2`。相關機制見 [官方模擬器網路說明](https://developer.android.com/studio/run/emulator-networking-address)。

## 可以驗證的範圍

- 登入、相簿瀏覽、TV 方向鍵操作及一般相簿的 Shuffle 開關。
- Screensaver 多相簿合併、去重、每輪播放與重新啟動的行為。
- 連接自己的伺服器後，大相簿是否能讀完，以及實際準備時的錯誤。

模擬器使用 PC 的 x86_64 CPU 與軟體圖形渲染。其啟動速度、影片解碼與記憶體表現，不能直接代表 TCL 的 ARM 硬體。四、五千張的測試可以先在 PC 找出功能問題；TCL 的實際效能、HDR／HEVC、長時間播放及系統自動進入 Screensaver，仍需在電視上驗收。

## 工具及故障處理

- 工具位於 `%LOCALAPPDATA%\ImmichTVPlus\android-sdk`；虛擬裝置名稱為 `ImmichTVPlus-API36`。
- 入口只針對 `emulator-5554` 操作，不會安裝到連接的實體手機／電視。若該連接埠被其他虛擬裝置占用，會停止並提示，避免操作錯誤裝置。
- 啟動失敗時，命令視窗會保留錯誤；模擬器紀錄在 `%LOCALAPPDATA%\ImmichTVPlus\logs`。
- 遙控器顯示「已送出」代表指令已送達，仍須觀察 TV 畫面的焦點或功能反應；在選單邊界按方向鍵可能不會移動。顯示「未送達」時先確認電視視窗仍開啟。遙控器只對指定名稱的測試模擬器送出指令。
- 已啟用虛擬裝置的硬體鍵盤支援，但主要建議使用 PC Remote，避免模擬器的鍵盤焦點與快捷鍵攔截問題。
- 模擬器占用約 2 GB 的客體 RAM，PC 另外需要模擬器程序與圖形處理的資源。測試期間可先關閉不需要的重型程式。
- `scripts/start-tv-emulator.ps1` 的 `-ResetAppData` 是供重設此測試裝置的選項，會清除虛擬電視內 Plus 的登入及設定；一般雙擊入口不會使用這個選項。

PC 測試入口最初搭配 1.0.0。後續認證修正版本與驗證情形，詳見 [Release 說明](release-guide.md)。

## 2026-10-20 操作修正驗證

使用者回報原本的鍵盤操作沒有反應後，新增 `scripts/tv-remote.py`，讓滑鼠按鍵透過 ADB 直接送到指定虛擬電視；硬體鍵盤設定也改為啟用。遙控器視窗已成功啟動，名稱為 `Immich TV Plus - PC Remote`。

已使用按鈕所呼叫的同一個輸入函式驗證：右鍵切換系統首頁的選取內容，左鍵返回原選取；確認鍵開啟系統 Screensaver 選擇清單，返回鍵關閉清單，沒有改變系統選用項目。驗證後已重新開啟 Plus，登入資料沒有清除。相同 APK 的雜湊比對及跳過重裝也已實際執行成功。

本輪 Windows 視窗自動化工具重試後仍回報 `failed to write kernel assets: 系統找不到指定的路徑。 (os error 3)`，因此以上是 ADB 輸入與 Android 畫面狀態驗證，未宣稱已完成 Windows 滑鼠點擊或原生鍵盤轉送的自動化驗證。

## 1.0.1 認證回歸驗證

在同一部模擬器建立獨立使用者，以只接受一份正確 `x-api-key` Header 的本機測試伺服器驗證：錯誤 Key 回應 401 且留在登入頁；正確 Key 通過認證、儲存值與使用中值一致，能開啟相簿和圖片；強制關閉後重開仍能讀取兩本相簿。遙控器貼上測試 Key 包含 `+`、`/`、`=`，可完整傳送。

測試完成已切回原使用者、刪除臨時測試使用者，重新開啟 App 與遙控器。未清除原使用者資料，也未使用其私人 Key 作為假伺服器測試資料。這項測試不代表真實伺服器的 401 已解決。

## 1.0.2 更換 Key 回歸

後續追查確認真實 Key 可正常驗證及讀取相簿；重開 App 後亦正常。以兩把公開假 Key，在 1.0.1 重現重新登入成功但首頁仍使用舊 Key 而 401。1.0.2 改為登入成功後釋放舊主畫面工作階段，同一測試已通過：首頁及回憶均回應 200，無 401；相簿、圖片與重開後登入皆正常。詳見 [正式回歸證據](../artifacts/qa/auth-session-fixed-1.0.2.json)。
